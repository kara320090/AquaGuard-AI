# AquaGuard AI Live Data Method

## 1. 목적

AquaGuard AI는 정적 공공데이터 기반 위험도에 더해, 기관이 공개한 최신 데이터를 자동 수집하여 현재 기준 농업용수 위험도를 갱신한다.

## 2. 수집 데이터

| 구분 | 데이터 | 역할 |
|---|---|---|
| 올담 | 최신 공개 저수율 CSV | 저수지 저장 상태 |
| 기상청 ASOS | 최근 30일 일자료 | 기준 기상 보조 |
| 기상청 AWS | 최근 30일 일강수량 | 15개 시·군 강우 부족도 |
| ADMS 토양수분 | 밭토양수분현황 | 실제 농지 건조 상태 |
| ADMS My 지역정보 | 시·군별 저수율 | 올담 저수율 교차검증 |

## 3. Live 위험도 산식

final_live_water_risk_score =
0.20 * live_rain_shortage_score
+ 0.20 * live_reservoir_risk_score
+ 0.20 * live_soil_moisture_drought_score
+ 0.15 * groundwater_dependency_score
+ 0.15 * crop_water_demand_score
+ 0.10 * alternative_source_access_shortage_score

## 4. 데이터 기준일 처리

시스템은 매일 자동 수집하지만, 기관이 공개한 최신 데이터의 기준일은 수집일과 다를 수 있다.

예를 들어 수집일이 2026-05-28이어도, 올담 저수율의 최신 측정일이 2026-05-22라면 시스템은 2026-05-22를 데이터 기준일로 보존한다.

이 방식은 오늘 날짜로 임의 보정하지 않고, 공개기관의 실제 기준일을 투명하게 드러내기 위한 설계다.

## 5. AWS 시·군 매핑 방식

현재 MVP에서는 충남 인근 AWS 관측소를 필터링한 뒤, 시·군 대표 좌표 기준 최근접 방식으로 시·군에 배정한다.

운영 고도화 단계에서는 행정경계 SHP 기반 point-in-polygon 방식으로 전환하여 행정구역 매핑 정확도를 높일 수 있다.

## 6. 해석 주의

본 시스템의 Live 데이터는 센서 단위 초실시간 스트리밍이 아니라, 기관이 공개한 최신 공개 데이터를 자동 수집하여 매일 갱신하는 방식이다.

따라서 발표 및 보고서에서는 “실시간 관측값”보다 “최신 공개 데이터 기반 Live 갱신”이라는 표현이 정확하다.
